## Commenting

### Let Code Speak
Write code that explains itself through structure and naming.

### Comment Sparingly
Add brief comments only when the logic isn't self-evident from the code.

### No Change Comments
Avoid comments about recent fixes or changes; comments should be timeless explanations, not changelogs.

### Sparse Rationale-Only Comments
Comment density is low (~10% of source lines) and comments explain rationale, workarounds, or contracts — never restate code. Do not leave TODO/FIXME/HACK markers or commented-out code; self-evident files carry no comments.
